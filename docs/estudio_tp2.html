Aprendizaje automático avanzado · TP2 · Construcción de un modelo de lenguaje

Modelos de lenguaje del TP2

Guía para estudiar todo lo que hicimos: cómo se predice la palabra siguiente con un perceptrón multicapa y con microgpt, partiendo de las representaciones del CBOW del TP1. Cada parte muestra el código, qué hace y los resultados de los dos.

Pablo Occhiuzzi · CBOW d = 50 Julián Ojeda · CBOW d = 80
§1

El recorrido

Las tres consignas comparten el mismo esquema. Primero se tokeniza el corpus, después el CBOW del TP1 da un vector por palabra (la matriz W) y, con esos vectores, cada modelo aprende a predecir el token que sigue.

Corpus1.053.788 tokens: palabras y signos en minúscula
CBOW (TP1)W: un vector de d componentes por palabra
ModeloPMC, microgpt o transformador: k tokens anteriores → puntaje por palabra
Siguiente tokensoftmax → se elige el más probable o se sortea

El TP pide un modelo causal: solo puede mirar los tokens anteriores. El CBOW del TP1, en cambio, ve el contexto de los dos lados para adivinar la palabra del medio.

§3

Los dos CBOW

El CBOW aprende un vector por palabra prediciendo la palabra central a partir del promedio de las de alrededor. Las filas de W son las «representaciones contextuales» que pide usar el TP2.

§4

Consignas 1 y 2: el PMC como modelo de lenguaje

Consigna 1Defina, implemente y entrene un perceptrón multicapa para que aprenda un modelo de lenguaje usando como corpus el utilizado en el TP1. Use las representaciones contextuales obtenidas en el TP1 y no use, en la implementación del perceptrón multicapa, una capa del tipo Embedding.

La entrada: vectores concatenados, sin capa Embedding

Para predecir el token siguiente se toman los k tokens anteriores, se busca la fila de cada uno en W y se pegan uno detrás del otro. Con k = 8 y d = 80 la entrada tiene 640 componentes; Pablo, con k = 5 y d = 50, tenía 250.

codigo/modelo_pmc_torch.py

def construir_entrada(W, contexto):
    # contexto: (B, k) índices de los k tokens anteriores
    return W[contexto].reshape(contexto.shape[0], -1)   # (B, k, d) -> (B, k*d)

# W NO es un parámetro: register_buffer la guarda y la mueve a la GPU, pero no se entrena
self.register_buffer("W", W)

Una capa Embedding (nn.Embedding) es justamente una tabla de vectores que se entrena. Acá la tabla es fija y viene del TP1, así que el PMC solo aprende a usarla.

Consigna 2Una opción es usar en la capa de salida tantas unidades como dimensión tenga la representación contextual, con activación logística o tangente hiperbólica, escalando las componentes a la imagen de la activación. Otra opción es usar una capa de salida softmax con tantas unidades como palabras haya en el vocabulario, con entropía cruzada como pérdida.

Las dos salidas

def perdida(self, contexto, objetivo):
    if self.modo == "vocabulario":
        # |V| = 53.409 salidas -> softmax -> entropía cruzada = -log p(palabra correcta)
        return F.cross_entropy(self.pmc(construir_entrada(self.W, contexto)), objetivo)
    # "vector": d = 80 salidas con tanh, contra el vector de la palabra correcta escalado a [-1, 1]
    return F.mse_loss(self.vector_predicho(contexto), self.W_escalada[objetivo])

def escalar_min_max(W, activacion_salida):
    W01 = (W - W.min()) / (W.max() - W.min())          # a [0, 1] (logística)
    return W01 if activacion_salida == "logistica" else 2 * W01 - 1   # a [-1, 1] (tanh)

En la variante «vector» el modelo devuelve un punto del espacio, no una palabra. Para leer qué predijo se buscan las palabras cuyo vector tiene mayor coseno con ese punto. Ese coseno es el «%» que aparece en las tablas de esa variante.

Por qué la salida «vector» predice palabras raras

Con error cuadrático, si el contexto admite muchas palabras siguientes («de», «la», «que»…), la mejor respuesta es el promedio de sus vectores. Ese promedio cae cerca del centro del espacio, donde están las palabras poco frecuentes, cuyos vectores el CBOW casi no movió de su inicialización. Por eso aparecen «díchole», «amanecieron» o «mucílago» en todas las frases. Le pasó a Pablo y le pasa al PMC de Julián («consultoras», «capiteles»), así que es una propiedad de la variante y no un error de código.

Cómo funciona microgpt

microgpt es un GPT completo en Python puro. Cada número es un objeto Value que recuerda de qué operación salió; así, después de calcular la pérdida, backward() aplica la regla de la cadena hacia atrás y obtiene el gradiente de cada parámetro.

material/autograd/microgpt.py

def __mul__(self, other):
    # c = a * b guarda a sus hijos (a, b) y las derivadas locales: dc/da = b, dc/db = a
    return Value(self.data * other.data, (self, other), (other.data, self.data))

def backward(self):
    # orden topológico y, desde la pérdida hacia atrás: grad_hijo += derivada_local * grad_nodo
    self.grad = 1
    for v in reversed(topo):
        for child, local_grad in zip(v._children, v._local_grads):
            child.grad += local_grad * v.grad

La función gpt() procesa un token por vez. Suma el embedding del token y el de su posición, aplica atención multi-cabeza y un MLP con conexiones residuales, y devuelve un logit por palabra. Las claves y valores de los tokens anteriores quedan guardados en listas, y por eso la atención es causal.

x = [t + p for t, p in zip(wte[token_id], wpe[pos_id])]   # embedding de token + posición
q, k, v = linear(x, W_Q), linear(x, W_K), linear(x, W_V)
keys.append(k); values.append(v)                           # solo existen las posiciones ya vistas
attn = softmax([q·k_t / raiz(dk) for k_t in keys])          # pesos de atención
x = x + linear(Σ attn_t · v_t, W_O)                         # residual
x = x + mlp(rmsnorm(x))                                     # d -> 4d -> d con ReLU
logits = linear(x, lm_head)                                 # un puntaje por palabra

Por qué es tan lento y por qué PCA

Cada multiplicación crea un objeto Value. Solo la última capa (lm_head) hace |V| × d multiplicaciones por token: con |V| = 1.158 y d = 80 son 92.640 objetos por token, y todos se recorren otra vez en backward(). Medido en esta computadora, un paso tardaba 17 s con d = 80 y 0,5% del corpus, y baja a 4,2 s con d = 40 y 0,3%.

Para no perder el vínculo con el TP1, wte sigue saliendo del CBOW, reducido con PCA: se centra W y se proyecta sobre las 40 direcciones de mayor varianza. Es la mejor aproximación de 40 dimensiones a las distancias entre palabras.

W_centrada = W_cbow - W_cbow.mean(axis=0)
_, valores_singulares, Vt = np.linalg.svd(W_centrada, full_matrices=False)
W_cbow = W_centrada @ Vt[:40].T                 # (|V|, 80) -> (|V|, 40)

§7

Cómo medir si un modelo anda

Entrenamiento contra validación

La pérdida de entrenamiento baja aunque el modelo solo esté memorizando. El PMC de Pablo dice «sexto» con 99% porque vio esa ventana exacta durante el entrenamiento. Para saber si generaliza hay que medir sobre texto que no vio: Julián deja afuera el 5% final del corpus, con una separación de k ventanas para que ningún objetivo de entrenamiento caiga dentro de una ventana de validación.

corte = int(T * (1 - 0.05))
indices_entrenamiento = np.arange(corte)
indices_validacion = np.arange(corte + k, T)     # k ventanas de separación

Contadores de ranking: top-5, top-10, top-20

El acierto exacto es injusto con un modelo de lenguaje: después de «hacia la» pueden venir «puerta», «ventana» o «esquina», y las tres están bien. Por eso se cuenta en qué puesto quedó la palabra correcta y si entró entre las primeras 5, 10 o 20.

codigo/modelo_completar_torch.py

def puesto_en_ranking(u, objetivo):
    u_correcta = u.gather(1, objetivo[:, None])     # puntaje de la palabra correcta
    return (u >= u_correcta).sum(dim=1)             # cuántas tienen puntaje >= (ella incluida)
# con >= un empate cuenta el peor puesto: si todas empatan, no hay acierto falso

Ejemplo: si la correcta tiene el 3.er puntaje más alto, su puesto es 3 y cuenta como acierto para los cortes 5, 10 y 20.

Perplejidad

La perplejidad es exp(pérdida): entre cuántas palabras «duda» el modelo en promedio. Una pérdida de validación de 5,93 equivale a una perplejidad de 376.

§8

Más allá de la consigna

Julián hizo además tres cosas que no pide el TP, pero que ayudan a entender los mismos temas.

1. El problema de la puntuación en el CBOW

El CBOW acertaba mucho prediciendo «,» y «.», que son muy frecuentes. Sin reentrenarlo desde cero, se lo ajustó 35 épocas más sin usar signos como palabra objetivo: el acierto en palabras subió de 63,0% a 66,7%.

2. CBOW + auto-atención

En lugar del promedio de las 8 palabras del contexto, una capa de atención aprende cuánto pesa cada una. La consulta es la posición central, y hay una «clave nula» para cuando ninguna palabra aporta. Se entrenó con PyTorch y su autograd, y antes se verificó contra gradientes calculados a mano en CuPy (diferencia de 8,5 · 10⁻⁸).

ModeloAcierto (palabra central)
CBOW con ajuste de puntuación (partida)66,7%
Mismo entrenamiento con la atención congelada (control)67,7%
CBOW + auto-atención71,2%

El control separa el efecto de la atención (+3,5 puntos) del efecto de entrenar más épocas (+1 punto).

3. Transformador causal con la arquitectura de la cátedra

Un bloque como el de las diapositivas de Transformadores, con normalización después de cada residual, vectores posicionales sinusoidales y cabezal u = h · Eᵗ con la misma matriz E del CBOW. N = 16, h = 4, L = 1, entrenado en PyTorch sobre el 95% del corpus.

codigo/modelo_completar_torch.py

def forward(self, X):
    T1, alfa = self.auto_atencion(X)    # Q K^t / raiz(dk) + máscara causal (-inf arriba de la diagonal)
    T2 = X + T1                         # residual
    T3 = self.normalizacion_1(T2)       # LayerNorm
    T4 = self.PMC_2(F.gelu(self.PMC_1(T3), approximate="tanh"))   # d -> 4d -> d
    T5 = T3 + T4                        # residual
    return self.normalizacion_2(T5), alfa

§9

Preguntas de repaso

Tocá cada pregunta para ver la respuesta.

¿Por qué no se puede usar nn.Embedding en el PMC?
Porque la consigna pide usar las representaciones del TP1. Una capa Embedding es una tabla que se entrena desde cero; acá la tabla W viene del CBOW y queda fija (register_buffer), y el PMC solo recibe sus filas concatenadas.
Con k = 8 y d = 80, ¿cuántas componentes tiene la entrada del PMC? ¿Y cuántos parámetros tiene la capa de salida «vocabulario» con 512 ocultas?
8 × 80 = 640 componentes. La capa de salida tiene 512 × 53.409 pesos + 53.409 sesgos ≈ 27,4 millones; es casi todo el modelo (27,7 millones en total).
¿Por qué hay que escalar W en la variante «vector»?
Porque tanh solo produce valores en [−1, 1] (y la logística en [0, 1]). Si el objetivo tiene componentes fuera de ese rango, el modelo nunca lo puede alcanzar. Con min-max global se lleva todo W a la imagen de la activación.
¿Por qué la variante «vector» termina prediciendo palabras raras?
Porque el error cuadrático premia predecir el promedio de las palabras posibles, y ese promedio cae cerca del centro del espacio, donde están las palabras poco frecuentes (sus vectores casi no se movieron en el CBOW). La softmax no tiene ese problema: reparte probabilidad entre las candidatas.
¿Qué hace Value.backward() en microgpt?
Ordena todos los nodos del grafo de forma topológica y recorre desde la pérdida hacia atrás, sumando a cada hijo derivada_local × gradiente_del_nodo (regla de la cadena). Se usa += porque un nodo puede influir en la pérdida por varios caminos.
¿Por qué la atención de microgpt es causal si no tiene una máscara?
Porque procesa un token por vez y solo agrega a keys/values las posiciones ya procesadas. Cuando está en la posición t, las posiciones futuras todavía no existen. En el transformador de PyTorch, que procesa las N posiciones juntas, hace falta la máscara con −∞ arriba de la diagonal.
¿Por qué microgpt tarda horas y el transformador de PyTorch minutos?
microgpt hace cada multiplicación como un objeto de Python (Value) y recorre ese grafo en el backward; PyTorch hace las mismas cuentas como multiplicaciones de matrices en la GPU. El algoritmo es el mismo; cambia la eficiencia.
¿Qué es PCA y por qué se usó en microgpt?
Es proyectar los vectores sobre las direcciones de mayor varianza (los primeros vectores singulares de W centrada). Se usó para pasar de d = 80 a d = 40 y que microgpt entrenara en horas, conservando el 67,6% de la varianza y la información del CBOW del TP1.
¿Por qué el PMC de Pablo dice «sexto» con 99% y el transformador de Julián no?
«los enanos tienen una especie de sexto» son las primeras palabras del corpus. El PMC con k = 5 vio exactamente esa ventana al entrenar y la memorizó. El transformador usa ventanas de 16 tokens, así que «sexto» (la 7.ª palabra) nunca fue objetivo de entrenamiento.
¿Qué mide el contador «top-5»?
El porcentaje de predicciones de validación en las que la palabra correcta quedó entre las 5 con mayor puntaje. Es más justo que el acierto exacto porque después de un contexto suelen caber varias palabras.
¿Cómo se detecta el sobreajuste en el transformador?
La pérdida de entrenamiento baja (5,70 → 3,18) mientras la de validación sube (5,93 → 10,03) y los contadores bajan. El mejor modelo es el de la época 1.
¿Para qué sirve el entrenamiento de control en CBOW + atención?
Para separar efectos: el control entrena las mismas épocas con la atención congelada. Ganó 1 punto solo por entrenar más; con atención se ganaron 4,5. La diferencia, 3,5 puntos, es lo que aporta la atención.

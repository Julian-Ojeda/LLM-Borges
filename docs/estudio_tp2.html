Modelos de lenguaje del TP2

Resolución de las tres consignas: un perceptrón multicapa y microgpt que predicen la palabra siguiente usando las representaciones del CBOW del TP1. Cada parte muestra el código, qué hace y los resultados de los dos. Al final hay un apéndice con autograd y microgpt explicados línea por línea.

Pablo Occhiuzzi · CBOW d = 50 Julián Ojeda · CBOW d = 80
§1

El TP y el recorrido

El TP2 pide construir un modelo de lenguaje: dado el comienzo de un texto, dar la probabilidad de cada palabra que puede venir después. Son tres consignas:

  1. Consigna 1: un perceptrón multicapa (PMC) que use las representaciones del TP1, sin capa Embedding.
  2. Consigna 2: dos formas de armar su capa de salida, un vector (tanh o logística) o una softmax sobre el vocabulario.
  3. Consigna 3: adaptar microgpt.py de Karpathy para que trabaje con palabras del corpus.

Las tres comparten el mismo esquema. Primero se tokeniza el corpus, después el CBOW del TP1 da un vector por palabra (la matriz W) y, con esos vectores, cada modelo aprende a predecir el token que sigue.

Corpus1.053.788 tokens: palabras y signos en minúscula
CBOW (TP1)W: un vector de d componentes por palabra
ModeloPMC o microgpt: tokens anteriores → puntaje por palabra
Siguiente tokense elige el más probable o se sortea

El modelo es causal: solo puede mirar los tokens anteriores. El CBOW del TP1, en cambio, ve el contexto de los dos lados para adivinar la palabra del medio. Por eso no alcanza con el CBOW y hace falta un modelo nuevo.

Los dos usamos el mismo corpus, datos/corpus_ApAvAu.txt, que empieza con «los enanos tienen una especie de sexto sentido…». Por eso varias de las frases de prueba de la presentación están dentro del corpus.

§3

El CBOW aprende un vector por palabra prediciendo la palabra central a partir del promedio de las de alrededor. Las filas de W son las «representaciones contextuales» que pide usar el TP2.

§4

Consigna 1: el PMC como modelo de lenguaje

Consigna 1Defina, implemente y entrene un perceptrón multicapa para que aprenda un modelo de lenguaje usando como corpus el utilizado en el TP1. Use las representaciones contextuales obtenidas en el TP1 y no use, en la implementación del perceptrón multicapa, una capa del tipo Embedding.

La entrada: vectores concatenados, sin capa Embedding

Para predecir el token siguiente se toman los k tokens anteriores, se busca la fila de cada uno en W y se pegan uno detrás del otro. Con k = 8 y d = 80 la entrada tiene 640 componentes; Pablo, con k = 5 y d = 50, tenía 250.

x = [ W[t₁] | W[t₂] | … | W[tₖ] ] → capa oculta (ReLU) → capa de salida

codigo/modelo_pmc_torch.py

def construir_entrada(W, contexto):
    # contexto: (B, k) índices de los k tokens anteriores
    return W[contexto].reshape(contexto.shape[0], -1)   # (B, k, d) -> (B, k*d)

# W NO es un parámetro: register_buffer la guarda y la mueve a la GPU, pero no se entrena
self.register_buffer("W", W)

Una capa Embedding (nn.Embedding) es justamente una tabla de vectores que se entrena. Acá la tabla es fija y viene del TP1, así que el PMC solo aprende a usarla.

El perceptrón

class PerceptronMulticapa(nn.Module):
    def __init__(self, dim_entrada, capas_ocultas, dim_salida, normalizacion, activacion):
        capas, anterior = [], dim_entrada
        for unidades in capas_ocultas:                  # [512] = una capa oculta de 512
            capas.append(nn.Linear(anterior, unidades))
            if normalizacion:
                capas.append(nn.LayerNorm(unidades))    # normalización por capa
            capas.append(ACTIVACIONES[activacion]())    # ReLU
            anterior = unidades
        capas.append(nn.Linear(anterior, dim_salida))   # |V| unidades o d unidades (consigna 2)
        self.red = nn.Sequential(*capas)

Con k = 8, una capa oculta de 512 y salida softmax, el modelo tiene 27,7 millones de parámetros. Casi todos (27,4 millones) están en la capa de salida: 512 × 53.409 pesos más 53.409 sesgos.

Los datos de entrenamiento

Una ventana de k tokens se corre de a uno por todo el corpus y el objetivo es el token que sigue. Así salen 1.053.780 ejemplos; el 5% final se separa para medir (ver §8).

ventanas = sliding_window_view(ids, k + 1)      # cada fila: k tokens de contexto + el siguiente
contexto, objetivo = ventanas[:, :k], ventanas[:, k]
§5

Consigna 2: las dos capas de salida

Consigna 2Una opción es usar en la capa de salida tantas unidades como dimensión tenga la representación contextual, con activación logística o tangente hiperbólica, escalando las componentes a la imagen de la activación. Otra opción es usar una capa de salida softmax con tantas unidades como palabras haya en el vocabulario, con entropía cruzada como pérdida.

Salida «vocabulario»

  • |V| = 53.409 unidades + softmax
  • Pérdida: entropía cruzada = −log p(palabra correcta)
  • Da directamente una probabilidad por palabra

Salida «vector»

  • d = 80 unidades con tanh o logística
  • Objetivo: el vector de la palabra correcta, escalado a la imagen de la activación
  • Pérdida: error cuadrático; la palabra se elige por coseno

codigo/modelo_pmc_torch.py

def perdida(self, contexto, objetivo):
    if self.modo == "vocabulario":
        # |V| = 53.409 salidas -> softmax -> entropía cruzada = -log p(palabra correcta)
        return F.cross_entropy(self.pmc(construir_entrada(self.W, contexto)), objetivo)
    # "vector": d = 80 salidas con tanh o logística, contra el vector de la palabra correcta escalado
    return F.mse_loss(self.vector_predicho(contexto), self.W_escalada[objetivo])

def escalar_min_max(W, activacion_salida):
    W01 = (W - W.min()) / (W.max() - W.min())                          # a [0, 1] (logística)
    return W01 if activacion_salida == "logistica" else 2 * W01 - 1   # a [-1, 1] (tanh)

def forward(self, contexto):                    # puntaje de cada palabra del vocabulario
    if self.modo == "vocabulario":
        return self.pmc(construir_entrada(self.W, contexto))           # logits
    y = F.normalize(self.vector_predicho(contexto), dim=1)
    return y @ F.normalize(self.W_escalada, dim=1).t()                 # coseno con cada palabra

En la salida «vector» el modelo devuelve un punto del espacio, no una palabra. Para leer qué predijo se buscan las palabras cuyo vector tiene mayor coseno con ese punto. Ese coseno es el «%» que aparece en las tablas de esa variante; no es una probabilidad.

Por qué la salida «vector» predice palabras raras

Con error cuadrático, si el contexto admite muchas palabras siguientes («de», «la», «que»…), la mejor respuesta es el promedio de sus vectores. Ese promedio cae cerca del centro del espacio, donde están las palabras poco frecuentes, cuyos vectores el CBOW casi no movió de su inicialización. Por eso aparecen palabras raras en todas las frases: «díchole», «amanecieron» o «mucílago» en el de Pablo, «sujet», «philosophie» o «judaeorum» en el de Julián. Es una propiedad de la variante y no un error de código. La softmax no tiene ese problema porque reparte probabilidad entre las candidatas.

Tanh contra logística: el coseno de la logística no discrimina

Pablo usó tanh; Julián probó las dos. Con la logística, W se escala a [0, 1]: todos los vectores tienen componentes positivas alrededor de 0,5 y apuntan casi en la misma dirección. Entonces el coseno entre el vector predicho y cualquier palabra da ≈ 1, y en las tablas todas aparecen con 99,8%. El orden sigue sirviendo para el top-5, pero el porcentaje no dice nada. Con tanh la escala es [−1, 1], centrada en 0, y el coseno sí separa las palabras.

# logística: W escalada a [0, 1]  ->  todos los vectores "miran" hacia (0,5; 0,5; ...; 0,5)
# coseno(y, W[j]) ≈ 0,998 para casi toda palabra j
# arreglo posible: centrar antes de comparar (restar 0,5) u ordenar por distancia euclidiana

Lote 256 contra lote 1

Con lote 1 los pesos se actualizan después de cada ejemplo (descenso por el gradiente estocástico «puro», como en el CBOW del TP1 y en tres de los PMC de Pablo). Con lote 256 se promedia el gradiente de 256 ejemplos y se da un solo paso. El lote grande aprovecha la GPU, que hace los 256 ejemplos en paralelo; con lote 1 procesa un ejemplo por vez.

Resultado: el lote 1 gana. Con la misma red y solo 2 épocas, la pérdida de validación baja a 5,48 (perplejidad 240, contra 420 del lote 256) y el top-5 sube de 34,6% a 41,1% (exacta 19,4% contra 15,4%). Además no se sobreajusta: la validación baja en las dos épocas (5,65 → 5,48). Cada ejemplo mueve los pesos, así que en una época se dan un millón de pasos chicos en vez de unos 4.000 promediados; el ruido de cada paso funciona como regularización y la tasa que decae hasta 0 afina al final.

Consigna 3: microgpt con palabras

Consigna 3A partir del código microgpt.py de Andrej Karpathy, realice las modificaciones para construir un modelo de lenguaje usando como corpus el del TP1. El vocabulario está dado por las palabras y signos de puntuación del corpus. Entrene con una fracción del corpus y verifique el correcto funcionamiento. Sugerencias: dimensión alrededor de 50; ventana de entrada de entre 5 y 10 tokens.

microgpt es un GPT completo en Python puro, sin librerías: cada número es un objeto Value que sabe calcular su propio gradiente. El original aprende a inventar nombres letra por letra. Cómo funciona por dentro está en los apéndices A y B; acá están solo los cambios para pasar de letras a palabras.

Qué hubo que cambiar

En el original un documento es un nombre («emma» → [BOS, e, m, m, a, BOS]). Acá un documento es una oración, y como una oración puede ser más larga que la ventana N, se corta en tramos de N + 1 tokens: N entradas y, para cada una, el token siguiente como objetivo.

Por qué es tan lento

Cada multiplicación crea un objeto Value. Solo la última capa (lm_head) hace |V| × d multiplicaciones por token: con |V| = 1.158 y d = 80 son 92.640 objetos por token, y todos se recorren otra vez en backward(). Por eso se usa una fracción chica del corpus (0,3%) y una sola época.

§8

Cómo medir si un modelo anda

Entrenamiento contra validación

La pérdida de entrenamiento baja aunque el modelo solo esté memorizando. El PMC de Pablo dice «sexto» con 99% porque vio esa ventana exacta durante el entrenamiento. Para saber si generaliza hay que medir sobre texto que no vio: Julián deja afuera el 5% final del corpus, con una separación de k ventanas para que ningún objetivo de entrenamiento caiga dentro de una ventana de validación.

corte = int(T * (1 - 0.05))
indices_entrenamiento = np.arange(corte)
indices_validacion = np.arange(corte + k, T)     # k ventanas de separación

Contadores de ranking: top-5, top-10, top-20

El acierto exacto es injusto con un modelo de lenguaje: después de «hacia la» pueden venir «puerta», «ventana» o «esquina», y las tres están bien. Por eso se cuenta en qué puesto quedó la palabra correcta y si entró entre las primeras 5, 10 o 20. Sirve igual para las dos salidas, porque las dos dan un puntaje por palabra (logit o coseno).

codigo/modelo_pmc_torch.py

def puesto_en_ranking(u, objetivo):
    u_correcta = u.gather(1, objetivo[:, None])     # puntaje de la palabra correcta
    return (u >= u_correcta).sum(dim=1)             # cuántas tienen puntaje >= (ella incluida)
# con >= un empate cuenta el peor puesto: si todas empatan, no hay acierto falso

Ejemplo: si la correcta tiene el 3.er puntaje más alto, su puesto es 3 y cuenta como acierto para los cortes 5, 10 y 20.

Perplejidad

La perplejidad es exp(pérdida): entre cuántas palabras «duda» el modelo en promedio. La pérdida de validación 6,04 del PMC de Julián con lote 256 equivale a una perplejidad de 420, y la de 5,48 con lote 1 a 240.

§9

Preguntas de repaso

Tocá cada pregunta para ver la respuesta.

¿Por qué no se puede usar nn.Embedding en el PMC?
Porque la consigna pide usar las representaciones del TP1. Una capa Embedding es una tabla que se entrena desde cero; acá la tabla W viene del CBOW y queda fija (register_buffer), y el PMC solo recibe sus filas concatenadas.
Con k = 8 y d = 80, ¿cuántas componentes tiene la entrada del PMC? ¿Y cuántos parámetros tiene la capa de salida «vocabulario» con 512 ocultas?
8 × 80 = 640 componentes. La capa de salida tiene 512 × 53.409 pesos + 53.409 sesgos ≈ 27,4 millones; es casi todo el modelo (27,7 millones en total).
¿Por qué hay que escalar W en la salida «vector»?
Porque tanh solo produce valores en [−1, 1] y la logística en [0, 1]. Si el objetivo tiene componentes fuera de ese rango, el modelo nunca lo puede alcanzar. Con min-max global se lleva todo W a la imagen de la activación.
¿Por qué la salida «vector» termina prediciendo palabras raras?
Porque el error cuadrático premia predecir el promedio de las palabras posibles, y ese promedio cae cerca del centro del espacio, donde están las palabras poco frecuentes (sus vectores casi no se movieron en el CBOW). La softmax no tiene ese problema: reparte probabilidad entre las candidatas.
¿Por qué con la logística todas las palabras salen con coseno ≈ 99,8%?
Porque al escalar W a [0, 1] todos los vectores quedan con componentes positivas cerca de 0,5: apuntan casi en la misma dirección, y el coseno mide dirección. Con tanh, W queda en [−1, 1] centrada en 0 y los vectores apuntan en direcciones distintas.
¿Qué cambia entre entrenar con lote 1 y con lote 256?
Con lote 1 se actualizan los pesos después de cada ejemplo: más pasos y más ruidosos. Con lote 256 se promedia el gradiente de 256 ejemplos y se da un paso por lote: menos pasos, más estables y mucho más rápidos en GPU.
¿Por qué el PMC de Pablo dice «sexto» con 99% y el de Julián no?
«los enanos tienen una especie de sexto» son las primeras palabras del corpus. Con k = 5, la ventana «enanos tienen una especie de» → «sexto» es un ejemplo de entrenamiento y Pablo la memorizó. Con k = 8, el primer ejemplo predice el 9.º token, así que «sexto» (el 7.º) nunca fue objetivo del PMC de Julián.
¿Qué hace Value.backward() en microgpt?
Ordena todos los nodos del grafo de forma topológica y recorre desde la pérdida hacia atrás, sumando a cada hijo derivada_local × gradiente_del_nodo (regla de la cadena). Se usa += porque un nodo puede influir en la pérdida por varios caminos.
¿Por qué la atención de microgpt es causal si no tiene una máscara?
Porque procesa un token por vez y solo agrega a keys/values las posiciones ya procesadas. Cuando está en la posición t, las posiciones futuras todavía no existen. Un modelo que procesa las N posiciones juntas (como los de PyTorch) necesita en cambio una máscara con −∞ arriba de la diagonal.
¿Para qué sirve el token BOS?
Marca el comienzo y el final de cada documento. Al principio es la entrada que no tiene nada antes; al final es el objetivo que enseña al modelo cuándo cortar. En la generación se arranca con BOS y se para cuando el modelo elige BOS.
¿Por qué microgpt es mucho más lento que el PMC?
microgpt hace cada multiplicación como un objeto de Python (Value) y recorre ese grafo en el backward; PyTorch hace las mismas cuentas como multiplicaciones de matrices en la GPU. El algoritmo de gradiente es el mismo; cambia la eficiencia.
¿Qué mide el contador «top-5»?
El porcentaje de predicciones de validación en las que la palabra correcta quedó entre las 5 con mayor puntaje. Es más justo que el acierto exacto porque después de un contexto suelen caber varias palabras.
¿Cómo se detecta el sobreajuste?
La pérdida de entrenamiento baja mientras la de validación sube. En el PMC de Julián con lote 256 pasa desde la época 2 (validación 6,04 → 6,47; con lote 1 no pasó en 2 épocas). Por eso se guarda el modelo de menor pérdida de validación.

Apéndice A

Autograd: cómo se calcula el gradiente

Para entrenar con descenso por el gradiente hace falta saber cuánto cambia la pérdida si se mueve un poco cada parámetro: la derivada parcial ∂E/∂w. En el CBOW del TP1 esas derivadas se escribieron a mano. Autograd las calcula solo: cada operación guarda de qué números salió y su derivada local, y después la regla de la cadena se aplica hacia atrás, desde la pérdida hasta cada parámetro.

1. Cada número recuerda de dónde salió

material/autograd/microgpt.py · clase Value

class Value:
    def __init__(self, data, children=(), local_grads=()):
        self.data = data                # el valor (cuenta hacia adelante)
        self.grad = 0                   # dE/d(este nodo), se llena en backward()
        self._children = children       # de qué Values salió
        self._local_grads = local_grads # derivada de este nodo respecto de cada hijo

    def __add__(self, other):           # c = a + b:  dc/da = 1,  dc/db = 1
        return Value(self.data + other.data, (self, other), (1, 1))

    def __mul__(self, other):           # c = a * b:  dc/da = b,  dc/db = a
        return Value(self.data * other.data, (self, other), (other.data, self.data))

    def __pow__(self, n):  return Value(self.data**n, (self,), (n * self.data**(n-1),))  # n a^(n-1)
    def log(self):         return Value(math.log(self.data), (self,), (1/self.data,))     # 1/a
    def exp(self):         return Value(math.exp(self.data), (self,), (math.exp(self.data),))  # e^a
    def relu(self):        return Value(max(0, self.data), (self,), (float(self.data > 0),))  # 1 o 0
    # resta, división, etc. se arman con las de arriba: a - b = a + (-1)*b,  a / b = a * b**-1

Con solo seis operaciones elementales y sus derivadas se puede armar cualquier red: un producto escalar es una suma de multiplicaciones, la softmax usa exp y una división, la entropía cruzada usa log.

2. La regla de la cadena, hacia atrás

def backward(self):
    # 1. Orden topológico: cada nodo aparece después de todos sus hijos
    topo, visited = [], set()
    def build_topo(v):
        if v not in visited:
            visited.add(v)
            for child in v._children:
                build_topo(child)
            topo.append(v)
    build_topo(self)
    # 2. Desde la pérdida hacia atrás: dE/dE = 1 y cada nodo le pasa su gradiente a sus hijos
    self.grad = 1
    for v in reversed(topo):
        for child, local_grad in zip(v._children, v._local_grads):
            child.grad += local_grad * v.grad      # regla de la cadena

El orden topológico garantiza que, cuando se procesa un nodo, ya se sumaron todas las contribuciones a su gradiente. Se usa += porque un mismo número puede influir en la pérdida por varios caminos (por ejemplo, un peso que se usa en cada token de la oración) y las contribuciones se suman.

3. Un ejemplo con números (el de la cátedra)

Una neurona con dos entradas y tanh, como en material/autograd/autograd-ApAuAv-UNAHUR.py: x₁ = 2, x₂ = 0, w₁ = −3, w₂ = 1, b = 6,88.

z = w₁·x₁ + w₂·x₂ + b = −6 + 0 + 6,88 = 0,88 salida = tanh(z) = 0,7064

Hacia atrás: d salida / dz = 1 − tanh²(z) = 1 − 0,7064² = 0,501. Después, cada multiplicación reparte ese gradiente con la regla «dc/da = b»:

NodoDerivada local respecto de zGradiente = local × 0,501
w₁x₁ = 21,002
x₁w₁ = −3−1,503
w₂x₂ = 00
x₂w₂ = 10,501
b10,501
 
x1, x2, w1, w2, b = Value(2.0), Value(0.0), Value(-3.0), Value(1.0), Value(6.88)
z = w1 * x1 + w2 * x2 + b
salida = (2 * z).exp()                     # tanh(z) = (e^2z - 1) / (e^2z + 1), armada con exp
salida = (salida - 1) / (salida + 1)
salida.backward()
print(w1.grad, x1.grad, w2.grad, b.grad)   # 1.002  -1.503  0.0  0.501

Interpretación: si w₁ sube un poco, la salida sube el doble de ese poco por 0,501 (gradiente 1,002). Como x₂ = 0, mover w₂ no cambia nada (gradiente 0). Para entrenar se mueve cada parámetro en contra de su gradiente: w ← w − η · w.grad.

PyTorch, que usa el PMC, hace exactamente esto, pero con matrices en lugar de números sueltos: perdida.backward() llena el .grad de cada parámetro y el optimizador da el paso.

Apéndice B

microgpt, parte por parte

microgpt.py entrena y usa un GPT en unas 200 líneas, sin librerías. Usa la clase Value del apéndice A para todo. El original trabaja con letras de nombres; en la consigna 3 los tokens son palabras (ver §6), pero el algoritmo es el mismo.

Notación: d = n_embd (dimensión), N = block_size (contexto máximo), H = n_head (cabezas), dk = d / H.

1. Datos y tokenizador

docs = [line.strip() for line in open('input.txt') if line.strip()]   # un nombre por línea
uchars = sorted(set(''.join(docs)))    # letras distintas: 'a' -> id 0, 'b' -> id 1, ...
BOS = len(uchars)                      # token especial: comienzo y fin de documento
vocab_size = len(uchars) + 1
# "ana" -> [BOS, a, n, a, BOS]   pares (entrada -> objetivo): BOS->a, a->n, n->a, a->BOS

2. Parámetros

matrix = lambda nout, nin, std=0.08: [[Value(random.gauss(0, std)) for _ in range(nin)] for _ in range(nout)]
state_dict = {
    'wte':     matrix(vocab_size, n_embd),     # embedding de cada token      (|V| x d)
    'wpe':     matrix(block_size, n_embd),     # embedding de cada posición   (N x d)
    'lm_head': matrix(vocab_size, n_embd),     # de d a un logit por token    (|V| x d)
}
for i in range(n_layer):
    state_dict[f'layer{i}.attn_wq'] = matrix(n_embd, n_embd)     # consultas (las H cabezas juntas)
    state_dict[f'layer{i}.attn_wk'] = matrix(n_embd, n_embd)     # claves
    state_dict[f'layer{i}.attn_wv'] = matrix(n_embd, n_embd)     # valores
    state_dict[f'layer{i}.attn_wo'] = matrix(n_embd, n_embd)     # mezcla las cabezas
    state_dict[f'layer{i}.mlp_fc1'] = matrix(4 * n_embd, n_embd) # MLP: d -> 4d
    state_dict[f'layer{i}.mlp_fc2'] = matrix(n_embd, 4 * n_embd) # MLP: 4d -> d
params = [p for mat in state_dict.values() for row in mat for p in row]   # lista plana para Adam

En la versión de palabras de Julián, wte no arranca al azar: cada fila es el vector de esa palabra en el CBOW del TP1.

3. Las piezas: linear, softmax y rmsnorm

def linear(x, w):                   # w (A x B) por x (B) -> vector de A
    return [sum(wi * xi for wi, xi in zip(wo, x)) for wo in w]

def softmax(logits):                # puntajes -> probabilidades positivas que suman 1
    max_val = max(val.data for val in logits)
    exps = [(val - max_val).exp() for val in logits]    # restar el máximo evita desbordes
    total = sum(exps)
    return [e / total for e in exps]

def rmsnorm(x):                     # divide por la raíz de la media de los cuadrados
    ms = sum(xi * xi for xi in x) / len(x)
    scale = (ms + 1e-5) ** -0.5
    return [xi * scale for xi in x]

rmsnorm es una versión simplificada de LayerNorm: no resta la media, solo lleva el vector a un tamaño parecido. Mantiene los números en una escala estable de capa en capa.

4. El modelo: la función gpt()

Procesa un token en la posición pos_id y devuelve los logits del siguiente. keys y values son la memoria de las posiciones anteriores: como cada llamada agrega solo la clave y el valor de su token, la atención solo puede mirar hacia atrás.

def gpt(token_id, pos_id, keys, values):
    x = [t + p for t, p in zip(state_dict['wte'][token_id], state_dict['wpe'][pos_id])]  # token + posición
    x = rmsnorm(x)
    for li in range(n_layer):
        # 1) Atención multi-cabeza
        x_residual = x
        x = rmsnorm(x)
        q = linear(x, state_dict[f'layer{li}.attn_wq'])
        k = linear(x, state_dict[f'layer{li}.attn_wk'])
        v = linear(x, state_dict[f'layer{li}.attn_wv'])
        keys[li].append(k)                  # este token queda visible para él y los siguientes
        values[li].append(v)
        x_attn = []
        for h in range(n_head):             # cada cabeza usa su porción de head_dim componentes
            hs = h * head_dim
            q_h = q[hs:hs + head_dim]
            k_h = [ki[hs:hs + head_dim] for ki in keys[li]]     # claves de las posiciones 0..pos_id
            v_h = [vi[hs:hs + head_dim] for vi in values[li]]
            attn_logits = [sum(q_h[j] * k_h[t][j] for j in range(head_dim)) / head_dim**0.5
                           for t in range(len(k_h))]            # q · k_t / raíz(dk)
            attn_weights = softmax(attn_logits)                 # cuánto mirar cada posición
            head_out = [sum(attn_weights[t] * v_h[t][j] for t in range(len(v_h)))
                        for j in range(head_dim)]               # promedio ponderado de los valores
            x_attn.extend(head_out)
        x = linear(x_attn, state_dict[f'layer{li}.attn_wo'])   # mezcla las H cabezas
        x = [a + b for a, b in zip(x, x_residual)]             # conexión residual
        # 2) MLP
        x_residual = x
        x = rmsnorm(x)
        x = linear(x, state_dict[f'layer{li}.mlp_fc1'])        # d -> 4d
        x = [xi.relu() for xi in x]
        x = linear(x, state_dict[f'layer{li}.mlp_fc2'])        # 4d -> d
        x = [a + b for a, b in zip(x, x_residual)]             # conexión residual
    return linear(x, state_dict['lm_head'])                    # un logit por token del vocabulario
atención(q, K, V) = softmax(q·Kᵗ / √dk) · V

La conexión residual (x + bloque(x)) deja pasar la información original y facilita que el gradiente llegue a las primeras capas. Con varias cabezas, cada una puede fijarse en una relación distinta (por ejemplo, una en el artículo anterior y otra en el verbo).

5. Entrenamiento: pérdida, backward y Adam

for step in range(num_steps):
    doc = docs[step % len(docs)]                         # un documento por paso (lote 1)
    tokens = [BOS] + [uchars.index(ch) for ch in doc] + [BOS]
    n = min(block_size, len(tokens) - 1)
    keys, values = [[] for _ in range(n_layer)], [[] for _ in range(n_layer)]
    losses = []
    for pos_id in range(n):
        token_id, target_id = tokens[pos_id], tokens[pos_id + 1]   # entrada y el que sigue
        probs = softmax(gpt(token_id, pos_id, keys, values))
        losses.append(-probs[target_id].log())           # entropía cruzada
    loss = (1 / n) * sum(losses)                         # promedio sobre el documento
    loss.backward()                                      # autograd: llena p.grad de cada parámetro

    lr_t = learning_rate * (1 - step / num_steps)        # la tasa baja linealmente hasta 0
    for i, p in enumerate(params):                       # Adam
        m[i] = beta1 * m[i] + (1 - beta1) * p.grad       # promedio del gradiente (dirección)
        v[i] = beta2 * v[i] + (1 - beta2) * p.grad ** 2  # promedio del cuadrado (escala)
        m_hat = m[i] / (1 - beta1 ** (step + 1))         # corrección: m y v arrancan en 0
        v_hat = v[i] / (1 - beta2 ** (step + 1))
        p.data -= lr_t * m_hat / (v_hat ** 0.5 + eps_adam)
        p.grad = 0                                       # si no, se acumularía al paso siguiente

Adam divide cada paso por la escala típica del gradiente de ese parámetro, así todos se mueven a un ritmo parecido aunque sus gradientes sean muy distintos. El PMC usa el mismo Adam (torch.optim.Adam con β₁ = 0,85 y β₂ = 0,99, los valores de microgpt) en sus corridas de lote 256.

6. Inferencia: generar texto

temperature = 0.5                       # menor: elige más seguido lo más probable
keys, values = [[] for _ in range(n_layer)], [[] for _ in range(n_layer)]
token_id, sample = BOS, []              # se arranca con BOS: "empieza un documento"
for pos_id in range(block_size):
    logits = gpt(token_id, pos_id, keys, values)
    probs = softmax([l / temperature for l in logits])
    token_id = random.choices(range(vocab_size), weights=[p.data for p in probs])[0]   # se sortea
    if token_id == BOS:                 # el modelo decidió terminar
        break
    sample.append(uchars[token_id])

La temperatura divide los logits antes de la softmax: con temperatura baja las diferencias se agrandan y casi siempre sale la palabra más probable; con temperatura alta la distribución se aplana y el texto es más variado (y más disparatado). La generación «ansiosa» de las tablas equivale a temperatura → 0: siempre la más probable.
